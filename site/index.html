When weather or a late aircraft disrupts a flight, air traffic control, the airline and the ground handler each hold part of the picture and settle it by phone. We gave each of them an AI agent that sees only its own organisation's data, a deterministic mediator, and hard safety rules, then replayed real 2015 US disruptions.

Architecture

Language models talk. Code decides what is allowed.

01 · INPUTA real DOT row

A delayed flight from flights.csv, its real neighbours and next leg, plus the organisers' workbook limits.

Code
02 · OPTIONSSimulator

Every combination of slot, ground or airborne delay, route and gate, with times, fuel and costs computed.

Code
03 · RULESThree checkers

Wake separation, capacity, taxiways, fuel reserve, crew duty, gates, notice, overtime. Each returns a rule ID and its source.

Code
04 · NEGOTIATEThree agents, one mediator

Each agent sees only its own data and picks moves. A deterministic mediator runs 3 turns, then imposes a fallback or escalates.

LLM picks moves
05 · DECIDEDuty manager

Every agent re-checks the final plan. The duty manager approves or overrides; the decision is appended to the hash-chained log.

Where the data comes from

RealDisrupted flight, schedule, delays, tail (flights.csv, DOT 2015) RealNext leg and its recorded knock-on delay (42% of rows) OrganiserRunways, gates, capacity, wake minima, fuel and crew rules (workbook; its capacity sheet is itself synthetic) SyntheticRest of the arrival stream, gate bookings, connecting passengers, crew start times, weather capacity cut, fuel on board

Every synthetic value is seeded and labelled per field. Every limit we changed or added is listed in scenarios/workbook.py.
